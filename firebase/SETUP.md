# Firebase 연결

1. 기존 firebase-config.js의 공개 웹 설정을 재사용합니다. 프로젝트는 riftbound-whale-28edd입니다. 서비스 계정 키는 브라우저 코드에 넣지 않습니다.
2. Authentication에서 익명 로그인을 활성화하고 사이트 도메인을 승인 도메인에 추가합니다.
3. Cloud Firestore와 Cloud Storage를 생성합니다. Storage는 결제 계정 연결이 필요할 수 있으므로 콘솔의 요금제 안내를 확인합니다.
4. 이 디렉터리의 Firestore / Storage 규칙은 T1 기능 전용입니다. 현재 콘솔의 기존 규칙을 먼저 보관하고, 해당 match 블록을 기존 규칙에 병합하세요. 기존 도감의 users 등 다른 규칙을 이 파일로 덮어쓰지 마세요. 전체 경로를 허용하는 기존 와일드카드 규칙이 있다면 T1 경로까지 허용하지 않도록 함께 조정합니다. Storage의 Firestore 규칙 조회 권한 요청도 승인합니다.
5. Storage 버킷에 실제 사이트 origin을 허용하는 GET CORS 정책을 적용합니다. 앱은 공개 다운로드 토큰 대신 규칙이 적용되는 getBlob을 사용합니다.
6. Firebase 콘솔에서 t1Reports 문서와 t1Evidence 사진을 확인하고 승인할 문서의 status만 approved로 바꿉니다. 거절은 rejected로 바꾸세요. 동일 선수/번호의 여러 제보는 통계에서 한 번만 셉니다. 승인 전 사진, 번호, 한국판 여부와 출처를 직접 확인하세요.
7. 실제 운영 전 App Check 적용 및 강제 적용, 업로드 할당량/예산 알림, 남용 방지 정책을 설정하세요. 현재 익명 인증은 로봇 방지나 제출 횟수 제한을 대신하지 않습니다. 관리자 클라이언트를 추가할 경우 Admin SDK로 설정한 admin 커스텀 클레임을 사용하세요.
8. 모바일 촬영/갤러리, PC 붙여넣기/드롭, 제출, 비공개 보관, 관리자 승인, 다른 기기에서 공개 기록 조회까지 연결된 프로젝트에서 확인하세요.

현재 config가 null이면 실제 저장을 수행하지 않고 명시적인 연결 전 상태를 표시합니다. 가짜 제보나 임의의 통계는 사용하지 않습니다. 미확인 번호는 미개봉 보장이 아닙니다.
