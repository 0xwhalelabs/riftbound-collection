# T1 한국판 아카이브 운영

기존 Firebase 프로젝트 riftbound-whale-28edd의 설정과 인증을 재사용합니다. 익명 인증, 서울 리전 Storage 버킷, Firestore 및 Storage 규칙을 연결했습니다.

새 제보는 pending 상태로 접수됩니다. 관리자가 /t1korean/admin에서 사진을 확인하고 승인하면 approved 상태로 공개됩니다. 승인 대기 중에도 해당 번호의 중복 접수를 차단합니다.

사인 박스는 category=box로 구분하며 도란·오너·페이커·케리아 각 5개, 총 20개입니다. 박스에는 시리얼 번호가 없으므로 사진을 필수로 접수하고 관리자가 사진과 출처로 중복 여부를 확인합니다. 문서 ID는 KR-BOX-{선수}-{자동 ID}이며 카드 시리얼과 별개입니다. 기존 category 필드가 없는 제보는 카드로 처리합니다.

문서 ID는 KR-{선수}-{번호}입니다. 예: KR-Faker-2025. Firestore 규칙은 이 ID와 입력값의 일치를 검증하고 생성만 허용합니다. 동시에 여러 명이 같은 번호를 제출해도 첫 등록만 성공하며 일반 사용자는 덮어쓸 수 없습니다.

사진은 t1Evidence/{uid}/{문서ID}/{0,1,2}.jpg에 저장됩니다. 승인 전에는 제보자와 관리자만 읽을 수 있고 승인 후 누구나 읽을 수 있습니다. /api/t1-image는 관리자 요청에만 사용자 인증 토큰을 전달하며 Storage 규칙이 읽기 권한을 확인합니다.

관리자는 /t1korean/admin에서 비밀번호로 로그인해 승인·삭제할 수 있습니다. 비밀번호는 Firebase Authentication에서 검증하며 소스에 저장하지 않습니다. 지정된 관리자 UID만 관리 권한을 가집니다. 관리자 계정 교체 시 두 규칙과 t1korean/admin-config.js의 UID를 함께 변경하세요. 관리자 전용 Firebase 앱과 세션 저장소로 카드 도감의 로그인 상태를 보존합니다.

삭제는 사진을 먼저 제거한 뒤 문서를 지웁니다. 삭제된 번호는 다시 접수할 수 있습니다. 사진 삭제 실패 시 문서를 남겨 재시도할 수 있습니다.

firestore.rules에는 기존 collections/{userId} 규칙을 보존했습니다. Firebase 콘솔에 다른 기능의 규칙이 추가되면 변경사항을 병합하세요. storage.rules는 T1 사진만 허용합니다. 미확인 번호는 실제 미개봉을 보장하지 않습니다.
